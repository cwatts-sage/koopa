## 📧 iMessage outgoing-address issue — confirmed from chat.db

Chris asked: *"So that setting is on the macOS iMessage settings?"* — **Yes.**
Messages → Settings (⌘,) → **iMessage** tab → **"Start new conversations from:"**

**Hard evidence from the database** (not inference):
```sql
SELECT DISTINCT account_login, service_name FROM chat WHERE service_name='iMessage';
  -> E:koopa7622@icloud.com

SELECT account, COUNT(*) FROM message WHERE is_from_me=1 AND <last 14 days> GROUP BY account;
  -> E:koopa7622@icloud.com | 187
```
**All 187 sent messages in the last 14 days went out as the email alias**, never the
phone number. That's why Geo sees `koopa7622@icloud.com` and his replies land in an
email thread we aren't reading.

Two sub-steps in that same pane:
1. "You can be reached for messages at" — the phone number must be **ticked** or it won't
   appear in the dropdown.
2. "Start new conversations from:" — set to the phone number.

⚠️ Changing it may restart Messages.app, which **kills the injected `imsg` dylib**
(typing indicators / read receipts). Re-run `imsg launch` afterwards — HEARTBEAT.md
already documents this watchdog.
