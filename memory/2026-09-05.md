## 🔬 Quantified the WFP_TEST_MODE risk precisely (was asserting it vaguely before)

**Good news — the lock ENFORCEMENT code is correct and well-built.** `api/picks/index.js`:
- GET computes `locked` per game (line ~78).
- POST validates picks, and on merge **keeps the existing pick for any locked game**,
  silently ignoring new input for it. No way to overwrite a locked pick.
- Extra guard: if ALL games in a week are scored → 403 "This week has been scored".

The security model is sound. **The ONLY problem is the flag flipping which rule applies:**
```js
const gameLocked = TEST_MODE ? scored : (scored || (lockTime && now >= lockTime));
```
With TEST_MODE=true, a game locks only once **scored** — and scoring is a MANUAL step
(`node score-week.js 1`), not automatic.
