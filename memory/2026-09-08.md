## 🔧 LESSON: `imsg send` hangs silently — use `send-rich`

Trying to reply to Geo, `imsg send --chat-id 12` **hung three times**: no output, no error,
process stuck in state S, nothing written to chat.db. Killed and retried, same result.

- `imsg status` reported bridge **healthy** the whole time (IMCore v2 connected).
- So a green `status` does NOT mean `send` works — they're different paths
  (`send` = AppleScript/Automation, `send-rich` = IMCore private API).
- **`imsg send-rich --chat 'any;-;+13038879556' --text "..." --json` worked instantly**,
  returned `{"queued":true,...,"guid":"F339A065-..."}`.
- Get the GUID via `imsg group --chat-id <id>`. Note `send-rich` takes `--chat` (guid),
  NOT `--chat-id`.
- `timeout`/`gtimeout` do NOT exist on this box — use `nohup ... &` + `sleep` + poll instead.

**Verify sends against chat.db** rather than trusting exit status:
`sqlite3 ~/Library/Messages/chat.db "SELECT datetime(m.date/1000000000+978307200,'unixepoch','localtime'), m.is_from_me FROM message m JOIN chat_message_join cmj ON m.ROWID=cmj.message_id WHERE cmj.chat_id=12 ORDER BY m.date DESC LIMIT 3;"`

Caught a near-miss this way: assumed the first send landed, DB showed last outbound was
09-07. Confirmed delivered 09-08 09:05:32.
