## NFL Pick 'Em — schedule times + stations FIXED

Chris flagged the app was missing real kickoff times and TV stations.

**Root causes found:**
1. All `broadcast` fields were null — original `load-2026-season.js` ran back in May before ESPN
   populated network data, so every game saved with an empty station.
2. Kickoff timestamps were malformed — stored as `2026-09-10T00:20Z` (no seconds). JS `Date`
   parses it leniently so nothing looked broken, but it was fragile.

**Built `webapp/scripts/refresh-schedule.js`** — pick-safe refresher:
- Updates ONLY `kickoff` + `broadcast` on existing matchup rows
- NEVER writes to `picks` or `standings`; never creates/deletes rows
- Uses MERGE (not Replace) so unknown columns survive
- Skips any game already final/scored
- Matches on team-pair (normalized), NOT row order — ESPN reorders games
- Never blanks an existing station if ESPN returns nothing
- Flags: `--dry-run`, `--weeks N|N-M`

**Results:** 271 kickoff timestamps normalized, 234 stations populated, 0 malformed remaining.
Networks now include NBC/CBS/FOX/ESPN-ABC/NFL Net + Netflix (49ers@Rams Wk1) + Prime Video (TNF).

**Phantom game found & removed:** `week-06` row 15 = "Dallas Cowboys @ Philadelphia Eagles" —
does not exist. Both teams already play others that week (Wk6 row 8 CAR@PHI, row 13 DAL@GB).
ESPN only has 14 Wk6 events; we had 15. Artifact from the May load. The team-pair matcher
caught it (refused to touch it) rather than silently overwriting. Deleted after verifying
picks table empty + no winner set. Season now 271 games (272 minus the phantom).

**Uneven week counts are NORMAL** — bye weeks. Wk7=13 games, Wk11=13, etc. Not corruption.

**Still outstanding:** 24 games (Wk17/18) have no station and Wk18 kickoffs are midnight-ET
placeholders (`2027-01-10T05:00Z`). NFL hasn't scheduled them — flex/playoff implications.

## Disk space — diagnosed, NOT fixed (deliberately)

Chris thought he'd grown the VM disk but wasn't sure how to extend the volume. He was right —
**26.8 GB unallocated** sitting on disk0. Currently 12 GB free / 45 GB fs, container 73.5% used.

**Why I did NOT resize.** Partition geometry (exact bytes):
- disk0s2 (main APFS) offset 524,308,480, ends at **48,318,402,560**
- disk0s3 (Recovery) starts at **48,318,402,560** ← zero gap, hard wall
- free 26.8 GB only begins AFTER Recovery

`diskutil apfs resizeContainer disk0s2 0` grows into space immediately following — that's
Recovery, not free space. On this box that's especially bad: **SIP disabled** (Recovery is the
only way to re-enable) + **FileVault on** + injected dylib in Messages. Not worth 26 GB.

**Options given to Chris (undecided):** (A) fix from hypervisor — need to know UTM/Parallels/
VMware/VirtualBuddy; (B) snapshot then remove disk0s3 + extend; (C) reclaim space instead
(brew cache, 33k-line gateway.log). Not an emergency at 50% capacity.
